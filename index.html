Dynamic crest factor reduction for a 5G RF SoC

Zephyr · multicore · interrupt-driven

The problem

OFDM modulation produces signals with a high peak-to-average power ratio. To stay linear at those rare peaks, the power amplifier must run far below its maximum output, where it is inefficient. Hard-clipping the peaks saves power but adds distortion.

The approach

Different parts of the signal tolerate different distortion. I implemented a dynamic clipping firmware that reads the EVM targets for each part of the signal and sets the hardware clipper in real time. Robust parts are clipped heavily and high-rate parts stay clean, so power drops while signal quality holds.

Firmware architecture

  1. Hardware interrupt
  2. ISR passes offset via Zephyr pipe
  3. Main thread parses buffer
  4. EVM target queue
  5. 4 worker threads, one per core
  6. Clipper hardware registers

The ISR stays minimal. The main thread sleeps until an interrupt arrives, and the workers compute clipper weights in parallel.

Test automation and CI for Zephyr and embedded Linux

Robot Framework · Jenkins · Yocto · SonarQube

The challenge

Validating firmware that runs on remote cores next to embedded Linux is hard, especially before silicon exists. Defects found late in integration are expensive, so I built automated tests and CI to catch regressions early.

The result

Unit tests and Robot Framework component tests cover the clipper’s core functionality. They ran first on a pre-silicon emulator, then moved to real hardware. Nothing merges without passing the quality gates, including at least 80% coverage.

Merge gate, on every push

  1. Push
  2. Build
  3. Unit tests
  4. Coverage ≥ 80%
  5. SonarQube gate
  6. Merge

Nightly pipeline

  1. Full Yocto image with Zephyr recipe
  2. Reserve emulator or board
  3. Boot Linux
  4. Load Zephyr on remote core via remoteproc
  5. Run Robot Framework tests
  6. Archive results
  7. Teams alert on failure
